# V2.2 P7 — Validación real de los projection adapters

Cierra la única fila parcial de la matriz V2.2 (STATUS.md §"V2.2: especificación absorbida y estado" → P7). Documenta el método para producir evidencia real de que cada adapter genera un archivo que el consumidor externo declara soportar, sin instalar el stack completo de cada GUI en CI.

## Source of truth

- **Interna (round-trip):** `archskillkit.projections` contract + el `World` que produce `archskillkit.promotion.discover` sobre el fixture canónico (`python/tests/conftest.py::kotlin_world_index` → 10 nodos, 5 edges, kinds variados). Los metrics del adapter (`ProjectionMetrics.nodes/edges`) son la verdad de salida que el contrato exige.
- **Externa (consumer):** el parser canónico del formato destino. No se valida contra la GUI del consumer (Cytoscape, draw.io, Obsidian, Arrows.app, LikeC4 view) sino contra el parser que esa GUI usa para construir su modelo interno. Si el parser acepta el archivo sin error y reconstruye el mismo número de nodos/edges con las mismas etiquetas, el archivo es portable a la GUI.

Esto evita instalar Cytoscape (~1 GB Java) y Gephi en CI: lo que importa no es que el botón "abrir" funcione en la GUI, sino que el modelo del archivo sea completo y conforme al spec que la GUI consume.

## Bar de evidencia por adapter

Para cada adapter, el validador produce en `artifacts/projections-validation/<adapter>/`:

1. **Artifact canónico** generado por el adapter sobre el fixture (`<adapter>.<ext>`).
2. **Parse estructural** con el parser del consumer:
   - GraphML → `lxml` (XML schema-aware) + `networkx` (round-trip a grafo).
   - JSON Canvas → `jsonschema` contra el spec de Obsidian Canvas (1.0).
   - draw.io → parse del `mxfile`/`mxGraphModel` + `lxml` round-trip.
   - Arrows → `jsonschema` contra el spec interno `arch-skillkit/arrows-v1`.
   - LikeC4 → `likec4` CLI `--validate` + `--output png` cuando está disponible.
3. **Reconciliation:** número de nodos/edges reconstruido por el parser vs metrics del adapter. Diff = 0 ⇒ PASS.
4. **Labels fidelity:** por cada nodo y edge, el `label` (o nombre de attribute) del archivo reconstruido coincide con el `name`/`kind` del fixture. Diff registrado en `reconciliation.md`.
5. **Snapshot hash** del archivo (SHA-256) — cualquier cambio futuro que rompa la portabilidad cambia este hash.

## Draw.io layout humano (P7 draw.io row)

El render visual del layout es decisión de la GUI de draw.io (auto-layout). Lo que validamos aquí es:

- El archivo parsea y reconstruye sin pérdida estructural (paso 3).
- El archivo abre en draw.io sin error — evidencia visual con `drawio-batch` o captura manual vía headless browser si están disponibles localmente; si no, captura diferida a la siguiente sesión de uso de draw.io.

El review humano del layout (qué tan fiel es a la fuente canónica) queda fuera de P7: es decisión de diseño de cómo presentar el grafo, no de portabilidad del archivo.
