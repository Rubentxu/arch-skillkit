# V2.4 Migration and Merge Notes

## 1. No migration de datos destructiva

V2.4 debe construir encima de V2.1–V2.3. No reescribir event history existente.

## 2. Documento 48

`48-v2.2-product-evolution.md` se conserva como propuesta histórica pero se considera superseded conceptualmente por V2.4.

Cambios principales:

- “CLI is the product” -> Architecture Intelligence Core;
- process registry in world -> RuntimeRegistry;
- score 0–100 primario -> Fitness Profile + score secundario;
- status shell commands -> typed actions;
- MCP después del Control Plane -> MCP antes o paralelo para estabilizar API;
- viewer process model -> Projection/Viewer separation;
- LikeC4-centric control plane -> multi-viewer orchestration;
- añade agent reasoning graph, candidate knowledge, sensor distillation, simulation y waivers.

## 3. Existing ProjectionAdapter

Mantener contrato y extenderlo de forma compatible. No meter `launch()` dentro de ProjectionAdapter.

Añadir Viewer layer separada.

## 4. Existing ArchitectureWorldPort

Introducir ports menores gradualmente. No big-bang rewrite. Primero read-side para status/explain/MCP, después mutation/governance.

## 5. Existing CLI

Extraer command functions/handlers uno a uno. Tests existentes deben seguir usando el entry point público.

## 6. Existing ContextCompiler

Conservar resultados actuales y añadir:

- ContextQuery;
- token/bytes/evidence-density metrics;
- KnowledgeGap refs;
- snapshot identity.

No romper `context --goal --subject` hasta deprecation explícita.

## 7. Existing Skills

`arch-orchestrator` continúa siendo entry point. Nuevas skills son delegadas cuando la tarea requiere profundidad. Mantener portability.

## 8. Existing ActiveGraph packs

`arch-core`, `arch-model`, `arch-code`, `arch-projections` permanecen. `arch-agent` y `arch-llm` se introducen sólo cuando M2/M4 confirmen contratos estables.

## 9. SemVer

No derivar versión Python desde la etiqueta “V2.4”. Cada release declara milestones implementados. Antes de merge corregir drift documental de `STATUS.md` respecto a `pyproject.toml`/latest tag.
