# Real OSS validation plan — Smoke + Tier-1 + Visualization

Goal: validate the `archskillkit` pipeline end-to-end against real code from
famous OSS projects, with architecture visualizations. Closes the
"P0..P7 Implemented in green but never proved on a non-synthetic repo"
gap that remains after the V2.1 UAT gate.

Scope: Smoke (CI) + Tier-1 (devbox sandbox on OSS) + Tier-2 (PNG render).
Out of scope: benchmarks (already covered by UAT2-017), production deploy.

## Resource policy — progressive, no hogging

The `archskillkit doctor` pins `4 scanner threads`; we never exceed that.
Linux caps below are mandatory for any Tier-1 run.

| Resource | Cap | Mechanism |
|----------|-----|-----------|
| CPU threads | **4** (matches scanner budget) | `taskset -c 0-3` + `--threads 4` to `archskillkit` |
| RAM | **8 GB hard, 6 GB soft** | `podman run --memory 8g --memory-reservation 6g` |
| Disk per project | **5 GB hard** (shallow clone + index + renders) | Pre-flight `df` check; teardown on finish |
| Wallclock per project | **30 min hard**, 20 min soft | `timeout --kill-after=60s 1800s`; soft check at 20 min |
| Concurrent runs | **1 project at a time** | Sequential B1 → teardown → B2; no parallelism |
| Host load avg | **< 2.0** before starting | `uptime` gate; skip + retry if higher |
| Background mode | Long scans run with `nice -n 19` so the user keeps the system interactive | `nice -n 19 ...` wrapper |
| Pause/resume | SIGSTOP / SIGCONT exposed via `scripts/oss/pause.sh <run-id>` | User can pause a scan and resume later |

Anything above the caps → the run aborts cleanly, evidence preserved, no
host contamination.

## Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Smoke count | 6 tests | Coverage of init/discover/project/context/drift + doctor |
| OSS projects | **Next.js + Axum + Django** | 3 idiomas (TS, Rust, Python); famosos; < 1GB |
| Sandbox mode | **Podman + devbox** | Hermeticidad real; reproducible en CI |
| Evidence model | sha256 + manifest, mismo patrón V2.1 gate | Ya tenemos `check-coverage.py` |
| Repo invariant | Read-only clone; `git status` limpio post-run | UAT2-001 invariant |
| Run order | Next.js → Axum → Django (size-ascending first run) | Quicker signal early; defer Django (largest) |
| Cross-project summary | `artifacts/oss/REPORT.md` | Vista unificada |
| Status.md update | Nueva fila "Real OSS validation" | Trazabilidad |

## Smoke tests (Tier 0)

Insertar entre `lint` y `test:python` en `mise run ci`. **Each smoke test
isolates its `ARCH_SKILLKIT_HOME` to `/tmp/ark-smoke-$$` and cleans up.**

| Test | Aserción | Tiempo | Recursos |
|------|----------|--------|----------|
| `smoke_doctor` | `archskillkit doctor` → status=ready | < 1s | 0 |
| `smoke_init_pollution` | init sobre tmp repo → status limpio (UAT2-001) | < 2s | 0 |
| `smoke_discover_kotlin` | 5-file Kotlin fixture → ≥1 architecture_element | < 5s | 1 thread, 256MB |
| `smoke_project_regen` | project both → likec4 validate → sha256 byte-identical en regen | < 5s | 1 thread, 512MB |
| `smoke_context_budget` | compile(`Budget(max_nodes=2)`) → respeta límites | < 3s | 256MB |
| `smoke_drift_deterministic` | forbidden dependency → drift findings sin LLM | < 3s | 256MB |

Total budget: ≤ 30s, max 1 thread at a time. No background jobs.

## Tier-1 (real OSS) — progressive

### Project selection by size

| Order | Proyecto | Repo | Idioma | LOC aprox | Tiempo estimado | Disco |
|-------|----------|------|--------|-----------|-----------------|-------|
| 1 | **Next.js** | `vercel/next.js` | TypeScript | ~100k | 8-12 min | 3 GB |
| 2 | **Axum** | `tokio-rs/axum` | Rust | ~30k | 4-6 min | 1.5 GB |
| 3 | **Django** | `django/django` | Python | ~200k | 12-18 min | 4 GB |

Total wallclock if all 3 pass: ~30-40 min spread over 3 sessions (one
project per session, never two sandboxes alive at once).

### Per-project pipeline (sequential, bounded)

1. **Pre-flight** (host-side, < 1s)
   - `loadavg=$(awk '{print $1}' /proc/loadavg)`; refuse if `> 2.0`
   - `free_avail=$(free -m | awk '/Mem:/{print $7}')`; refuse if `< 8192`
   - `df_avail=$(df -BG /tmp | awk 'NR==2{gsub("G","");print $4}')`; refuse if `< 5`
2. **Clone** (≤ 90s)
   - `git clone --depth 1 --bare --filter=blob:none <repo> /tmp/ark-oss-<x>` 
   - Pre-flight check: `du -sh <bare>` < 1GB else abort
3. **Sandbox** (Podman, ≤ 30s)
   - `podman run -d --name ark-<x> --rm --memory 8g --memory-reservation 6g --cpus 4 --pids-limit 1024 --tmpfs /tmp fedora:39 sleep infinity`
   - Mount `<bare>` read-only at `/src:ro` in container
4. **Tooling** (≤ 60s)
   - `mise trust` + `mise install` for the runtime tools (ast-grep, semgrep, likec4)
   - Run `archskillkit doctor` → must be `ready`; else abort
5. **Ingest** (≤ 5 min, `--threads 4`)
   - `archskillkit ingest-code --repo /src --exclude '**/node_modules/**' --exclude '**/.venv/**' --max-target-bytes 5MB`
   - Watch RAM via `podman stats ark-<x> --no-stream`; abort if > 7 GB sustained
6. **Discover + Review** (≤ 5 min)
   - `archskillkit discover --repo /src` + `archskillkit review --repo /src`
7. **Project** (≤ 2 min)
   - `archskillkit project --repo /src --format both`
8. **Drift** (≤ 1 min)
   - `archskillkit drift --repo /src`
9. **Render (Tier-2)** (≤ 3 min)
   - `likec4 export --png --output render/` for system + container
   - Skip if Chrome unavailable (R1)
10. **Evidence** (≤ 10s)
    - `sha256sum * > evidence/manifest.txt`
11. **Invariante UAT2-001** (≤ 5s)
    - Compare `git -C <bare> status` before vs after; must be identical
12. **Teardown** (≤ 10s)
    - `podman rm -f ark-<x>`
    - `rm -rf <bare> /tmp/ark-oss-<x>`
    - `podman image prune -f` only if no other ark-* containers exist

Each step writes a checkpoint to `artifacts/oss/<x>-<date>/runs/<step>.log`
so a paused/aborted run can be resumed without re-running the prior steps.

### Pause/resume control

`scripts/oss/pause.sh <run-id>` → `kill -STOP $(pgrep -f ark-oss-<run-id>)`
`scripts/oss/resume.sh <run-id>` → `kill -CONT $(pgrep -f ark-oss-<run-id>)`

Documented in `scripts/oss/README.md` so the user can free the system when
they need to do something else.

## Tier-2 (visualization)

For each completed Tier-1 run, render once:
- `likec4.c4` → `likec4-system.png` (vista de sistema)
- `likec4.c4` → `likec4-container.png` (vista de contenedor)
- `arrows.arrows` (importable en arrows.app)
- `canvas.json` (importable en Obsidian JSON Canvas viewer)

PNG render happens INSIDE the sandbox while it still has the index, so we
don't need to keep the bare repo on disk after the sandbox tears down.
Skip PNG if Chrome unavailable (R1); capture likec4 source + validate as
text evidence.

## Estructura de artefactos

```
artifacts/oss/
  nextjs-<YYYYMMDD>/
    runs/<step>.log for each pipeline step
    scan.json  ingest.json  discover.json  review.json  drift.json  context.json
    project/
      likec4.c4  arrows.arrows  canvas.json
    render/
      likec4-system.png  likec4-container.png (si Chrome disponible)
    evidence/manifest.txt
    report.md
  axum-<YYYYMMDD>/  django-<YYYYMMDD>/
  REPORT.md
```

`runs/<step>.log` is gitignored; everything else lives under `artifacts/`
(gitignored at repo level, same pattern as the V2.1 UAT gate evidence).
The committed state carriers are: `report.md` content quoted in
STATUS.md, the sha256 `evidence/manifest.txt` per run, and this plan.

## Sandbox lifecycle (devbox + Podman)

Cada `scripts/oss/oss-<x>/justfile`:

- `setup` — pre-flight + podman run + mise trust/install + doctor
- `clone` — `git clone --depth 1 --bare --filter=blob:none`
- `scan` — `archskillkit ingest-code` con caps
- `discover` — `archskillkit discover`
- `review` — `archskillkit review`
- `project` — `archskillkit project --format both`
- `drift` — `archskillkit drift`
- `render` — `likec4 export --png` (opcional)
- `evidence` — sha256sum + manifest
- `teardown` — podman rm + rm bare + optional image prune

## Riesgos y mitigaciones

| ID | Riesgo | Mitigación |
|----|--------|-----------|
| R1 | likec4 PNG render necesita Chrome | Skip PNG; likec4 source + validate como evidencia |
| R2 | Semgrep escanea vendor/ | `--exclude` patterns + `--max-target-bytes 5MB` |
| R3 | Repo OSS > 1GB | Pre-flight `du -sh`; abort if over budget |
| R4 | Idioma no soportado | Solo escanear repos en {Python, TS, Kotlin, Rust} |
| R5 | Podman no instalado | Fallback a env-based hermeticidad; documentar |
| R6 | Scan > 30 min por repo | Soft check at 20 min, hard `timeout 30m` |
| R7 | OSS repos tiene credenciales reales en tests | Redact antes de capturar evidencia; documentar en report.md |
| R8 | Host overload por scans concurrentes | Sequential only + `nice -n 19` + loadavg gate |
| R9 | User necesita el sistema mientras corre un scan | SIGSTOP via `scripts/oss/pause.sh` |

## Plan de sesiones

**Sesión A — Smoke suite** (~45 min, no OSS)
- Crear `scripts/smoke/` con los 6 tests (todos con caps y `ARCH_SKILLKIT_HOME` aislado)
- Wire a `mise run ci` entre `lint` y `test:python`
- 6/6 PASS en synthetic repo
- Commit + push

**Sesión B — Next.js end-to-end** (~30 min, scoped)
- Podman sandbox con caps (`--cpus 4 --memory 8g`)
- Pipeline completo: clone → ingest → discover → project → render → evidence
- Verificar invariante UAT2-001
- Teardown completo
- `artifacts/oss/nextjs-<date>/` con sha256
- Commit + push (1 proyecto confirmado antes de seguir)

**Sesión C — Axum end-to-end** (~20 min)
- Mismo flujo
- Cross-OSS report inicial con 2 proyectos
- Commit + push

**Sesión D — Django end-to-end** (~45 min)
- Mismo flujo, repo más grande → respeta caps
- `artifacts/oss/REPORT.md` final
- `docs/v2/STATUS.md`: nueva fila "Real OSS validation" = Implemented
- Posible tag v0.4.1 con la evidencia como release notes

Cada sesión termina con teardown limpio: ningún sandbox vivo, ningún bare
repo en `/tmp`, ningún proceso background consumiendo recursos.

## Criterios de éxito

- 6/6 smoke tests verdes dentro de `mise run ci` (< 30s total)
- 3/3 proyectos OSS escaneados end-to-end
- ≥ 6 PNG renders con sha256 verificado (2 niveles × 3 proyectos) si Chrome disponible
- Invariante UAT2-001: 3/3 repos OSS con `git status` limpio post-run
- `archskillkit doctor` → ready en cada sandbox
- `artifacts/oss/REPORT.md` con LOC, #components, #relations, drift findings por proyecto
- Post-validación: 0 procesos background, 0 sandboxes vivos, `/tmp` < 5GB ocupado por ark-* paths

## Decisiones de scope abiertas

- Si podman falla en host → fallback a env-based hermeticidad (R5)
- Si likec4 render falla → degradar Tier-2 a text-only (R1)
- Si el scan excede timeout → descartar el proyecto y reportar (R6)
- Si Chrome no está disponible → skip PNG y degradar Tier-2 a text (R1)
