# v2.5 — Smoke OSS Validation Plan

Goal: Human-reviewed validation of the real-OSS smoke campaign produced by
`smoke-oss.sh` across 3 slots (Rust, TypeScript, Kotlin). This plan explains
how to navigate the evidence artifacts and render a PASS / PARTIAL / FAIL
verdict without re-running the pipeline.

## Artifact hierarchy

```
$STABLE_ROOT/                      (XDG: ~/.local/share/sddk/projects/p-f58d41952fdf56c1/oss-smoke)
├── INDEX.md                       ← cross-slot overview, one row per run
├── manifest.json                  ← machine-readable cross-slot summary
├── UAT.md                         ← cross-slot human acceptance test document
├── smoke-YYYYMMDDHHMMSS-N/       ← per-run directory (N = slot number)
│   ├── commit.txt                 ← cloned git SHA
│   ├── frontmatter.txt            ← YAML frontmatter (pinned_sha, pin_source, campaign_id, slot_id, run_date)
│   ├── git-before.txt             ← git status --porcelain after clone
│   ├── git-after.txt              ← git status --porcelain after pipeline (must == git-before.txt)
│   ├── UAT.md                     ← per-run human acceptance test
│   ├── evidence/
│   │   ├── manifest.txt           ← sha256 of every evidence file
│   │   └── scan.astgrep.jsonl    ← ast-grep scan results (if run)
│   └── <slot_id>/<date>/
│       ├── RUN_INDEX.md           ← slot-level index with checklist
│       └── RUN_MANIFEST.yaml      ← machine-readable slot manifest
```

## How to read a smoke campaign

### Step 1 — Open `$STABLE_ROOT/INDEX.md`

This file lists every smoke run ever recorded. Look for the row matching your
review session. The `verdict` column tells you the derived outcome for each
slot run. A `*` marker may appear next to superseded (hollow) runs.

### Step 2 — Open `$STABLE_ROOT/manifest.json`

Machine-readable summary. Each entry maps a `run_id` to its `verdict`,
`pin_match`, `clone_size_mb`, and `wallclock_seconds`. Use this to
programmatically aggregate results across slots.

### Step 3 — Open `UAT.md` (cross-slot)

`$STABLE_ROOT/UAT.md` contains the cross-slot acceptance test with 5
human-reviewable steps. Verify each step is satisfied before signing off.

### Step 4 — Per-slot deep dive

For each slot you wish to audit:

1. Open `<run-id>/<slot_id>/<date>/RUN_INDEX.md`
2. Check every checkbox is ticked
3. Open `<run-id>/<slot_id>/<date>/RUN_MANIFEST.yaml`
4. Confirm `verdict`, `pin_match`, `uat2_001`, and `cleanup_audit` fields

## The 3-point checklist

Every smoke run must satisfy all three hard invariants. If any one fails,
the run is **FAIL**.

| # | Invariant | How to verify |
|---|-----------|---------------|
| 1 | **Pin binding** — cloned SHA matches pinned SHA | `grep pin_match RUN_MANIFEST.yaml` → must be `true` |
| 2 | **Repo immutability** — git status identical before/after (UAT2-001) | `diff git-before.txt git-after.txt` → must be empty |
| 3 | **Evidence complete** — evidence/manifest.txt non-empty | `wc -l evidence/manifest.txt` → must be ≥ 1 |

## Verdict semantics

| Verdict | Meaning |
|---------|---------|
| **PASS** | All 3 hard invariants satisfied. Evidence is complete and traceable. |
| **PARTIAL** | Artifacts are present but at least one hard invariant is not satisfied. Review the `verdict_reason` field in `RUN_MANIFEST.yaml`. |
| **FAIL** | A hard invariant failed. The run is invalid for review. See `RUN_MANIFEST.yaml` for the specific failure reason. |

## Superseded-run policy

A run may be marked **superseded** when a subsequent run of the same slot
produces newer evidence. The `INDEX.md` file marks superseded runs with a
`*` marker and records the run ID that replaced them in the `supersedes`
field of `RUN_MANIFEST.yaml`.

When reviewing, always use the newest non-superseded run for each slot.
Superseded runs are retained for traceability but must not be used as the
sign-off artifact.

## References to REQ-OSS-SMOKE-* IDs

This plan covers validation evidence for the following requirements:

- REQ-OSS-SMOKE-SHABinding — pinned SHA bound to cloned SHA
- REQ-OSS-SMOKE-CloneSize — clone size ≤ 1024 MB per slot
- REQ-OSS-SMOKE-CleanupAudit — zero ark-smoke residue post-run
- REQ-OSS-SMOKE-UATHuman — UAT.md with ≥ 5 human-reviewable steps
- REQ-OSS-SMOKE-ArtifactIndex — per-slot RUN_INDEX.md and RUN_MANIFEST.yaml
- REQ-OSS-SMOKE-NoDevboxEdit — devbox.json unchanged throughout
- REQ-OSS-SMOKE-PinEachRun — pin refresh via gh API before clone
- REQ-OSS-SMOKE-Frontmatter — 5-line YAML frontmatter
- REQ-OSS-SMOKE-Wallclock — wallclock ≤ 10 min per slot
- REQ-OSS-SMOKE-VerdictDerivation — FAIL-on-missing hard invariants

## How to re-run a slot

To re-run a specific slot (for example, slot 1):

```bash
SDDK_DATA_DIR=~/.local/share/sddk \
  scripts/oss/smoke-oss.sh slot1-rust 1 \
  https://github.com/Rubentxu/software-development-decision-kernel
```

To re-run all slots in sequence:

```bash
SDDK_DATA_DIR=~/.local/share/sddk \
  for slot in "slot1-rust:1:https://github.com/Rubentxu/software-development-decision-kernel" \
              "slot2-ts-saas:2:https://github.com/calcom/cal.diy" \
              "slot3-kotlin:3:https://github.com/Rubentxu/pipeline-kotlin"; do
  IFS=':' read -r sid sn url <<< "$slot"
  SDDK_DATA_DIR=~/.local/share/sddk scripts/oss/smoke-oss.sh "$sid" "$sn" "$url"
done
```

## Evidence review checklist

Before signing off a smoke campaign:

- [ ] `INDEX.md` lists all 3 slots with verdict PASS
- [ ] `manifest.json` has 3 entries with `pin_match: true` and `verdict: PASS`
- [ ] Each `RUN_MANIFEST.yaml` has `uat2_001: true`, `cleanup_audit` pass
- [ ] Each `evidence/manifest.txt` is non-empty with ≥ 1 sha256 entry
- [ ] No `git-before.txt` / `git-after.txt` diff exists (UAT2-001)
- [ ] `devbox.json` SHA matches `c7e9279e…` (no modification)
