# V2.4 — Architecture Intelligence & Agent Governance

Status: PROPOSED

## 1. Visión

**ArchSkillKit construye un modelo temporal y verificable de la arquitectura del software a partir de evidencias, y lo utiliza para explicar, gobernar y guiar de forma segura cambios realizados por personas y agentes de IA.**

La idea de producto deja de ser “generar diagramas desde código” y pasa a ser un **digital twin arquitectónico evidence-backed**.

## 2. Diferenciadores

1. **Derived**: el punto de partida es código, configuración, build metadata y sensores, no un DSL manual.
2. **Evidence-backed**: claims y relaciones automáticas conservan provenance.
3. **Temporal**: event sourcing, snapshots y deltas permiten explicar cuándo y por qué apareció conocimiento.
4. **Governed**: drift, fork, proposal, review, promote y waivers forman un workflow explícito.
5. **Graph-native**: objetos, relaciones y causalidad son la semántica central.
6. **Agent-native**: ContextPack, Prompt Compiler, Skills, MCP, explicit AgentSession y candidate knowledge.
7. **Projection-agnostic**: LikeC4, Arrows, draw.io, JSON Canvas, GraphML, Excalidraw y formatos futuros son lentes del mismo conocimiento.
8. **Learning**: descubrimientos recurrentes de agentes pueden destilarse a sensores deterministas.
9. **Local/open/portable**: el núcleo funciona sin un SaaS obligatorio y preserva artefactos intercambiables.

## 3. Cambio de principio respecto a doc 48

No usar “CLI is the product”. Adoptar:

> **The Architecture Intelligence Core is the product; CLI, MCP and HTTP/Control Plane are delivery adapters.**

El CLI sigue siendo la UX de referencia y superficie estable para automatización, pero no puede convertirse en el centro arquitectónico.

## 5. Resultados de V2.4

- `ArchitectureSnapshot` canónico e identificable por digest.
- `RunLedger` separado de `ArchitectureWorld`.
- `RuntimeRegistry` efímero para procesos/ports/viewers.
- Application API estable con DTOs tipados.
- `ark status`, `schema`, `explain`, `impact`, `ask`, `view`, `history`, `gate`.
- Viewer Registry y Control Plane multi-viewer.
- `arch-agent`/`arch-llm` packs y skills especializadas.
- MCP 2026-07-28 compatible, read-only por defecto.
- Knowledge Gaps y Evidence Requests de primera clase.
- counterfactual `simulate/guard` sobre forks.
- Fitness Profile multidimensional; score compuesto sólo secundario.
- architecture waivers/debt ledger.
- SARIF y reportes PR.
- agent sessions con snapshot/version lease.
- sensor distillation y conformance mining como fase de aprendizaje.

## 6. No objetivos

- crear un IDE de diagramación propio;
- sustituir LikeC4/draw.io/Excalidraw/yEd/Gephi;
- importar millones de símbolos del Code Index al Architecture World;
- framework multiagente monolítico;
- chat genérico sin grounding;
- auto-promoción de conocimiento LLM;
- convertirse en un scanner SBOM/SLSA generalista;
- añadir otro lenguaje propio por rendimiento potencial.
