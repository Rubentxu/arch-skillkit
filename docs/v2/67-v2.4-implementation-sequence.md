# V2.4 Guided Implementation Sequence

Este documento traduce el roadmap a una secuencia de cambios pequeña y verificable sobre el código actual.

## Slice 0 — Documentation gate

1. Merge docs V2.4.
2. Actualizar STATUS/ADR index.
3. Marcar doc 48 superseded by V2.4.
4. Ejecutar suites baseline.

No cambiar behavior todavía.

## Slice 1 — DTOs y snapshot

Crear paquete sugerido:

```text
archskillkit/application/
  __init__.py
  models/
    snapshot.py
    actions.py
    delta.py
  queries/
  commands/
```

Implementar `ArchitectureSnapshot` como manifest compacto, no como copia arbitraria de todo el graph.

Tests:

- canonical serialization;
- stable digest;
- changed revision -> changed digest.

## Slice 2 — Ports y read-side use cases

Evolucionar `ports.py` o dividir gradualmente:

```text
ports/
  architecture_query.py
  evidence_query.py
  code_graph_query.py
  history.py
  governance.py
```

Primero `GetStatus` y `Explain`.

No migrar todas las mutaciones en una PR.

## Slice 3 — RunLedger / RuntimeRegistry

Sugerencia:

```text
archskillkit/runtime_state/
  run_ledger.py
  runtime_registry.py
```

- SQLite para ledger si el spike lo confirma;
- JSON/SQLite/lockfile pequeño para runtime registry;
- interface/test in-memory.

## Slice 4 — CLI handlers

Extraer comandos nuevos en handlers:

```text
archskillkit/delivery/cli/
  status.py
  explain.py
  schema.py
```

`cli.py` queda como parser/composition root/transitional dispatcher.

No reescribir argparse completo salvo necesidad.

## Slice 5 — Viewer layer

```text
archskillkit/viewers/
  contract.py
  registry.py
  router.py
  system_default.py
  likec4.py
  drawio.py
```

Mantener `projections/` independiente.

Probar:

- probe availability;
- launch argv;
- runtime registry lifecycle;
- no world mutation.

## Slice 6 — ContextQuery + metrics

Añadir typed query encima de ContextCompiler actual sin romper CLI legacy.

Instrumentar bytes/lines/tokens/evidence density antes de optimizar lectura parcial.

## Slice 7 — Impact / Unknowns

Implementar `AnalyzeImpact` usando CodeIndex traversal + architecture refs.

Introducir KnowledgeGap sólo con casos UAT reales; no construir toda ontología agentic de golpe.

## Slice 8 — Governance read models

- Run history;
- ArchitectureDelta;
- Fitness Profile;
- gate rules.

Antes de Control Plane.

## Slice 9 — Agent core

Crear sólo cuando los schemas de M2 sean estables:

```text
archskillkit/packs/arch_agent/
  object_types.py
  relation_types.py
  behaviors.py
  tools.py
  prompts/
```

Primera capability: `InferenceCandidate` + `KnowledgeGap` + review fixture.

## Slice 10 — MCP

```text
archskillkit/delivery/mcp/
  server.py
  tools.py
  resources.py
  prompts.py
  auth.py
```

Optional dependency extra. E2E read-only primero.

## Slice 11 — Simulation

Usar ActiveGraph fork existente. Aplicar graph mutation candidate en fork, ejecutar policies y devolver delta. No inventar un segundo simulation engine.

## Slice 12 — Control Plane

Sólo después de estabilizar Application API/MCP schemas.

```text
archskillkit/delivery/web/
  server.py
  api.py
  static/
```

El frontend consume APIs tipadas y Viewer Registry.

## Slice 13 — Learning

Sensor distillation como vertical completo pequeño sobre un patrón real. No construir “auto-learning framework” genérico primero.

## Regla de PR size

Cada slice debe poder:

- pasar CI;
- conservar repo read-only invariant;
- incluir schema/test/UAT impact;
- no requerir el siguiente slice para ser coherente.
