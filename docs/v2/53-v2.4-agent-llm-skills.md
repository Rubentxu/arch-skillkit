# V2.4 Agent, LLM, Prompt and Skills Architecture

## 1. Regla principal

> Deterministic systems observe. LLMs hypothesize. The graph remembers. Policies decide.

Los agentes son participantes del knowledge workflow, no autoridades sobre el accepted world.

## 2. Tres modos de integración

```text
External Agent + Skill + CLI
            \
             +--> Application API --> ActiveGraph
            /
External Agent + MCP

Embedded LLM behavior --> LLMProviderPort --> Candidate Knowledge
```

Todos deben producir/consultar los mismos DTOs y domain commands.

## 3. Roles lógicos

Conservar el principio existente: roles no implican procesos permanentes ni framework multiagente.

### Deterministic Scanner

- identifica y ejecuta sensores;
- produce Observation/Evidence;
- no interpreta arquitectura compleja.

### Discovery / Architecture Scout

- busca elementos, boundaries e integraciones;
- formula `Hypothesis` y `KnowledgeGap`;
- solicita targeted reads.

### Evidence Scout

- elige la evidencia siguiente con mejor relación information-gain/cost;
- consulta CodeIndex primero;
- source read sólo dirigido.

### Modeler

- propone claims/relaciones/vistas;
- nunca promueve directamente.

### Contradiction Reviewer

- busca evidence contradictoria;
- marca conflicts;
- puede solicitar second opinion para high-impact/low-confidence.

### Projection Intelligence

- genera `ProjectionEnrichment` renderer-neutral;
- selecciona focus, overlays, grouping, narrative;
- no modifica los ficheros de salida directamente.

### Sensor Distiller

- detecta inferencias LLM repetidas;
- crea `SensorCandidate` con positivos/negativos y propuesta ast-grep/Semgrep;
- requiere tests/UAT antes de promoción.

### Conformance Miner

- identifica patrones arquitectónicos repetidos;
- propone `ArchitectureRuleCandidate`;
- nunca convierte correlación observada en regla sin aprobación.

## 4. Selective deliberation

No llamar LLM para trabajo ya resuelto deterministicamente.

Triggers candidatos:

- confidence baja;
- evidence contradictoria;
- alta centralidad con poca evidence;
- gran cambio entre snapshots;
- elementos sin clasificar;
- KnowledgeGap high-impact;
- pattern repeated across runs;
- solicitud explícita de explicación/enrichment.

## 5. Candidate Knowledge contract

Toda salida LLM estructurada contiene:

- output schema version;
- snapshot_id;
- agent_run_id;
- prompt_revision/hash;
- skill_revision/hash;
- model/provider identity cuando se conozca;
- context_pack_id/hash;
- evidence_refs;
- confidence;
- rationale breve estructurado, no chain-of-thought;
- uncertainties;
- requested_followups.

## 6. Prompts

Los prompts son versionados e identificables por digest. Cambiar contenido sin cambiar versión debe seguir siendo detectable por hash.

Prompts mínimos V2.4:

- evidence-scout;
- hypothesis-extractor;
- contradiction-reviewer;
- projection-enricher;
- sensor-distiller.

Ver `design/prompts/v2.4/`.

## 7. Skills

Las Skills son la capa portable de workflow para Claude Code/Codex/Cursor/Windsurf/OpenCode/otros hosts.

Skills propuestas:

- `arch-investigation`;
- `arch-projection-intelligence`;
- `arch-reviewer`;
- `arch-sensor-distillation`.

`arch-orchestrator` sigue siendo entry point y debe delegar, no absorber toda la documentación.

## 8. AgentSession

Una sesión referencia un snapshot explícito:

```text
session_id
snapshot_id
world_revision
code_generation
policy_revision
budget
scope
created_at
```

Si cualquier revision crítica cambia, devolver `SESSION_STALE` o avisar explícitamente. El agente debe refrescar contexto.

## 9. Multi-model fork/diff

Sólo para casos justificados:

```text
impact=high AND confidence<threshold
OR evidence=contradictory
```

Cada modelo produce candidate subgraph en un fork. Comparar objetos/relaciones/unknowns, no prosa.

## 10. Learning loop

```text
LLM discovers
  -> Candidate Knowledge
  -> Evidence validates
  -> Policy/Human accepts
  -> repetition detected
  -> SensorCandidate
  -> fixtures + tests
  -> deterministic SensorPackRevision
```

Objetivo: reducir progresivamente dependencia del LLM donde el patrón ya es aprendible y verificable.
