## S24-05 Excalidraw

> **Estado: EJECUTADO (2026-09-02, M1). Decisión: DEFER a M5.**

Hallazgos verificados (docs oficiales + repo):

- **Formato**: `.excalidraw` es JSON plano versionado (`type:
  "excalidraw"`, `version: 2`) con `elements[]`, `appState`, `files`.
  ✓ importable/exportable sin dependencia del editor.
- **IDs estables**: cada elemento tiene `id` de cadena persistente,
  `version`/`versionNonce` por cambio y `customData` para metadata de
  extensión — soportaría semantic links y round-trip si se adoptara. ✓
- **Embedding**: componente oficial `@excalidraw/excalidraw` (React)
  con `initialData`/`onChange`/API imperativa; también excalidraw.com
  como WEB_HANDOFF. ✓
- **Licencia**: MIT (repo excalidraw/excalidraw) — sin fricción de
  bundle para un frontend. ✓
- **Valor diferencial frente a lo ya adoptado**: JSON Canvas cubre el
  mapa de investigación (Obsidian) y draw.io cubre el diagrama técnico
  editable con embed + round-trip prioridad alta. El diferencial de
  Excalidraw es el flujo de boceto/explicación, cuyo hogar natural es
  el Control Plane (M5).

**Decisión**: DEFER. En M1 no se adopta como formato ni viewer: no
mejora aún ningún workflow existente frente a JSON Canvas/draw.io y su
integración valiosa (componente React embebido) depende de la decisión
de stack frontend del Control Plane (spike S24-07). **Re-evaluar en
M5**: si S24-07 adopta React, añadir `ExcalidrawViewer`
(EMBEDDED + WEB_HANDOFF, capabilities edit/round_trip) para el workflow
boceto→propuesta; si no, queda WEB_HANDOFF puro vía excalidraw.com y
se cierra definitivamente.
