# V2.5 Metrics and Quality Gates

## 1. Regla

No usar un score único para ocultar dimensiones.

Cada gate publica:

- ID;
- dimensión;
- métrica;
- threshold;
- current;
- status;
- evidence.

## 2. Architecture integrity

- `arch_delivery_cross_imports`: target 0.
- `arch_application_concrete_imports`: target 0.
- `arch_activegraph_leaks`: target 0.
- `arch_graph_structural_leaks`: target 0.
- `arch_baseline_debt_count`: tendencia monotónica descendente.
- `application_api_coverage`: 100% de capabilities externas.

## 6. Governance

## 7. Packaging

- direct dependency completeness = 100%;
- clean wheel smoke = pass;
- offline deterministic tests = pass where declared;
- locked environment resolution = pass.

## 8. Quality gate classes

### BLOCKING

Invariante de seguridad/corrección.

### MIGRATION-BLOCKING

No permite nueva deuda; baseline existente tolerado.

### TREND

Se mide para orientar mejoras, no bloquea aún.

### UAT

Requiere ejecución sobre fixture/target real.

## 9. No score washing

Si existe score agregado, un BLOCKING FAIL nunca puede quedar oculto por score
alto en otras dimensiones.
