# V2.4 Governance, Impact and Counterfactual Simulation

## 1. Governance model

Gobernar arquitectura significa distinguir:

- realidad detectada;
- conocimiento inferido;
- arquitectura aceptada;
- intención/propuesta;
- excepción temporal;
- deuda conocida.

## 2. Fitness Profile

La señal primaria es multidimensional, no un score único:

```yaml
freshness:
  status: pass|warn|fail|na
  value:
evidence_coverage:
unknown_coverage:
drift:
review_debt:
policy_coverage:
projection_validity:
sensor_coverage:
unexplained_change:
```

Un score 0–100 puede existir para badge/trend como proyección secundaria, siempre derivado de dimensiones publicadas y con N/A explícito.

## 3. Gates

Preferir invariantes explícitas:

```text
ark gate --no-new-drift
ark gate --min-evidence-coverage 0.80
ark gate --max-unexplained-relations 3
ark gate --no-expired-waivers
ark gate --require-fresh-index
```

`--min-fitness` sólo convenience aggregate.

## 4. Architecture Debt Ledger

Objects:

- Waiver;
- ArchitectureDebt;
- OwnerRef;
- Expiry;
- Rationale;
- ADRRef opcional.

Nunca “ignorar” drift. Convertirlo en excepción gobernada.

Gate example:

```text
0 new drift
3 accepted waivers
1 waiver expires in 7 days
2 architecture debts overdue
```

## 5. Architecture Delta

Comparar snapshots, no sólo counts:

- elements added/removed/changed;
- relations added/removed/changed;
- boundaries changed;
- evidence coverage delta;
- unknowns opened/resolved;
- policies affected;
- waivers delta;
- sensor coverage delta.

## 6. Impact

Input puede ser file, symbol, endpoint, architecture element, relation o proposal.

Output:

- code dependants;
- architecture dependants;
- interfaces;
- persistence/message channels;
- policy/rule impact;
- evidence that may stale;
- affected projections;
- risk hints;
- ContextPack.

## 7. Counterfactual simulation

Feature clave:

```text
Current Snapshot
    |
    v
ActiveGraph fork
    |
apply hypothetical graph mutation
    |
    +--> policy evaluation
    +--> drift evaluation
    +--> blast radius
    +--> projection preview
    +--> knowledge gaps
    |
    v
SimulationResult
```

No modificar source code ni accepted main world.

Commands candidates:

```text
ark simulate relation add Orders Payments
ark simulate move PaymentService --to billing-context
ark guard --change change.yaml
```

## 8. SimulationResult

- base_snapshot;
- fork id;
- proposed graph delta;
- violated rules;
- warnings;
- unknowns;
- blast radius;
- fitness profile delta;
- required evidence;
- recommendation `allowed|risky|blocked|unknown`.

“recommendation” es policy result, no opinión LLM.

## 9. PR integration

`ark report pr` / gate report:

- base/head snapshot;
- architecture delta;
- new/resolved drift;
- new/expired waivers;
- evidence coverage delta;
- impacted elements;
- SARIF findings;
- links/refs a projections.

## 10. SARIF

Prioridad alta por integración nativa con code scanning UIs. Mapping mínimo:

- finding/rule id;
- severity;
- source file/range cuando exista;
- architecture object ids;
- evidence refs;
- remediation/proposal link.

## 11. Attestation

Future-ready `ark attest`:

- snapshot digest;
- git commit;
- sensor revisions;
- tool versions;
- policy revision;
- artifact manifest;
- evidence manifest digest.

Reutilizar disciplina Sigstore ya adoptada para releases; no duplicar un sistema de firma casero.
