# V2.4 Projection, Viewer and Control Plane Specification

## 1. Separación fundamental

`ProjectionAdapter` responde “¿cómo genero un formato?” y `ViewerAdapter` “¿cómo visualizo/edito ese formato?”.

```text
Architecture World
      |
      v
ProjectionAdapter
      |
      v
ProjectionArtifact
      |
      v
ViewerRouter
      |
      +--> Viewer A
      +--> Viewer B
```

Un formato puede tener N viewers y un viewer puede consumir N formatos.

## 2. Projection formats

Baseline productivo actual:

- LikeC4;
- Arrows;
- draw.io;
- JSON Canvas;
- GraphML.

V2.4 candidate:

- Excalidraw directo;
- Mermaid/DOT/D2/PlantUML como derived projections donde resulte barato y útil.

## 3. ViewerDescriptor

Capabilities mínimas:

- consumes formats;
- `view`;
- `edit`;
- `embedded`;
- `local_process`;
- `web_handoff`;
- `round_trip`;
- `autosave`;
- `semantic_links`;
- `probe` method/capability.

## 4. Viewer modes

### EMBEDDED

Dentro del Control Plane.

Candidates:

- LikeC4 Web Component;
- draw.io embed mode;
- Excalidraw component/viewer.

### MANAGED_SERVER

ArchSkillKit inicia servidor local y registra PID/port en RuntimeRegistry.

Candidate: `likec4 serve/start`.

### LOCAL_PROCESS

Abre una app instalada con el artifact.

Candidates:

- draw.io Desktop;
- VS Code + Arrows extension;
- Obsidian Canvas;
- yEd;
- Gephi;
- Cytoscape.

### WEB_HANDOFF

Abre/importa artefacto en web app cuando exista integración segura.

## 5. Fallback

`SystemDefaultViewer` utiliza asociación del SO (`xdg-open`, `open`, equivalente Windows) sin convertir aplicaciones desconocidas en dependencias del dominio.

## 6. Viewer Registry

Interfaz conceptual:

```text
probe()
capabilities()
can_open(artifact)
launch(artifact, mode)
stop(session)
receive_changes() optional
```

`ark viewers` y `ark doctor` consumen el mismo registry.

## 7. Control Plane

No es renderer ni editor. Es una shell de:

- navegación de snapshots;
- evidencia/provenance;
- history/delta;
- governance;
- investigation/unknowns;
- viewer embedding/launch;
- suggestions/actions;
- run traces.

## 8. draw.io

Usar embed mode oficial cuando se implemente edición integrada. El host carga XML mediante `postMessage` y recibe export/save events. Nunca aceptar una edición del diagrama como arquitectura automáticamente.

Pipeline de round trip:

```text
ProjectionArtifact
  -> editor
  -> modified artifact
  -> ProjectionDelta
      -> presentation changes
      -> semantic candidates
  -> Proposal/Review
```

## 9. Semantic vs Presentation State

Presentation-only:

- x/y;
- color;
- size;
- zoom;
- waypoints;
- grouping visual.

Semantic:

- element addition/removal;
- architecture relation addition/removal;
- kind/boundary change;
- ownership/policy semantics.

No contaminar Architecture World con layout salvo `PresentationProfile` separado.

## 10. ProjectionEnrichment

Renderer-neutral:

```yaml
focus: payment-service
overlays: [confidence, evidence, drift]
group_by: bounded_context
highlight: [boundary_crossings]
narrative:
  - public API
  - event publication
annotations: []
```

Cada adapter traduce lo soportado y devuelve warnings por capacidades no representables.

## 11. Projection lifecycle

- GENERATED;
- STALE;
- MANUALLY_MODIFIED;
- CONFLICTED;
- SUPERSEDED.

Conservar generated digest + source snapshot + adapter version.

## 12. Security

- localhost por defecto;
- token/session local para Control Plane;
- no arbitrary filesystem paths desde browser;
- origin/CSRF protection si hay writes;
- governance writes deshabilitados por defecto;
- viewers externos considerados trust boundaries.
