# V2.5 Control Plane and Delivery Architecture

## 1. Principio

El Control Plane es una superficie del Application API. No es un segundo
backend.

## 2. Responsabilidades HTTP

Permitidas:

- routing;
- authn/authz;
- validation de transporte;
- HTTP status mapping;
- serialization;
- static UI serving.

No permitidas:

- construir dominio;
- implementar proposal workflow;
- reutilizar CLI handlers;
- capturar stdout;
- decidir policy;
- mutar `world.graph`.

## 3. Estructura

```text
adapters/inbound/http/
  server.py
  routes.py
  request_mapper.py
  response_mapper.py
  security.py

adapters/inbound/webui/
  static/
```

## 4. Seguridad

Defaults:

- loopback;
- read-only;
- write/admin explícito;
- mutation endpoints pasan por commands;
- CSRF/origin policy cuando aplique;
- no exponer filesystem arbitrario.

## 5. CLI

CLI debe terminar siendo:

```text
parse args -> application command/query -> render result -> exit code
```

## 6. MCP

MCP debe terminar siendo:

```text
decode tool call -> application command/query -> encode MCP result/error
```

No debe fabricar `argparse.Namespace`.

## 7. Strangler

Los comandos legacy se migran uno a uno. Cada migración elimina una entrada del
baseline `delivery_to_delivery` o `legacy_wiring`.
