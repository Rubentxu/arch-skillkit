# V2.4 Security, Trust and Governance Boundaries

## 1. Trust zones

- source repository: read-only input;
- XDG workspace: writable product state;
- ArchitectureWorld: governed durable knowledge;
- RuntimeRegistry: ephemeral/untrusted process state;
- external viewers: separate trust boundary;
- external LLM/MCP clients: untrusted principals unless explicitly authorized.

## 2. LLM policy

- no secret inclusion by default;
- Context Compiler filters/path policies before provider call;
- record provider/model metadata without persisting credentials;
- prompts/context hashes persist; raw sensitive prompt payload persistence configurable;
- candidate outputs never auto-promote.

## 3. Tool Gateway

Todas las capacidades agentic deben pasar por una policy layer que conoce:

- requested capability;
- session/snapshot;
- mutation scope;
- path allowlist;
- budgets;
- authorization tier;
- audit event.

## 4. MCP tiers

- READ: default;
- PROPOSE: opt-in;
- ADMIN: explicit local/config authorization.

No confiar en que “el cliente es Claude/Cursor” como autenticación.

## 5. Control Plane

Default:

- bind `127.0.0.1`;
- random local session token;
- read-only domain operations;
- CSP apropiada;
- validate origin/CSRF para writes;
- no arbitrary file serving;
- no shell command injection through ViewerDescriptor parameters.

## 6. Viewer launch

Commands deben ser argv arrays tipados, nunca templates ejecutados con `shell=True` por defecto.

User-configured viewers requieren placeholder allowlist (`{artifact}`, `{workspace}`) y sanitización.

## 7. Projection imports

Archivos modificados externamente son input no confiable:

- parse con schema/size limits;
- no ejecutar contenido;
- separar semantic candidates de presentation;
- require review antes de domain mutation.

## 8. Evidence and source privacy

Context/LLM provider policy configurable:

- local-only;
- allow metadata but not snippets;
- allow bounded snippets;
- provider allowlist.

Cada ModelCall registra policy aplicada.

## 9. Attestation

Firmar manifests/snapshots con mecanismos maduros (Sigstore) donde aporte valor. No firmar cada node/event individualmente salvo threat model futuro que lo justifique.
