## 1. Vision

**One sentence**: turn `arch-skillkit` from a library with a CLI into the
*architecture intelligence layer* for humans and AI agents — a model
**derived from code** (not hand-drawn), **evidence-backed** (every claim
has provenance), **governed** (drift → fork → proposal → promote), and
**served** to agents (budgeted context packs, MCP, control plane).

## 2. Design principles

1. **CLI is the product.** No shell scripts exposed to users; everything
   is `archskillkit` (alias `ark`). Scripts remain internal CI plumbing.
2. **State inference over commands.** Every command infers project state
   and suggests the next action (`git status`-style hints). Agents never
   guess; users never memorize.
3. **Two output contracts.** `--json` (schema-versioned, stable) for
   agents and tooling; human-readable by default. `ark schema <cmd>`
   prints the JSON Schema of any command — self-describing.
4. **Visualizers are managed processes.** `ark view` spawns, tracks
   (PID registry in world state), and stops viewers. Nothing background
   without `ark view --list` showing it.
5. **Evidence over vibes.** Every number the product shows links to the
   event log / evidence manifest that produced it.

## 3. CLI surface (target)

Existing commands keep their names (init, state, replay-verify, ingest-code,
index-stats, search-code, discover, review, context, project, drift, fork,
diff, promote, reject-proposal, setup, doctor). New:

### 3.1 `ark status` — state inference (M1, highest leverage)
Read-only. Inspects repo + world + index + registry and emits:
```json
{
  "schema": "arch-skillkit/status-v1",
  "project": {"id": "...", "root": "...", "tracked": true},
  "world": {"exists": true, "runs": 3, "last_run_at": "...",
             "stale_since_scan": false},
  "index": {"symbols": 21315, "edges": 55, "generation": "oss-nextjs",
             "older_than_worktree": false},
  "architecture": {"elements": 87, "relations": 55, "drift_findings": 0},
  "fitness": {"score": 82, "grade": "B", "components": {...}},
  "next": [
    {"action": "discover", "reason": "index older than last commit",
     "cmd": "ark discover --repo ."},
    {"action": "review", "reason": "7 observations unreviewed", ...}
  ]
}
```
The `next[]` suggestions are the agent loop primitive: any LLM agent can
poll `ark status --json` and execute the suggested `cmd` list. Exit code
always 0 (it is a report, not a check).

### 3.2 `ark view [likec4|arrows|drawio|canvas|graphml]` — managed viewers (M1)
- Regenerates the projection if stale (compares `generated_sha256`),
  then launches the right viewer **as a tracked process**:
  - `likec4` → `likec4 start` server on localhost (workspace pinned to
    the projection dir — the CWD gotcha becomes untestable-by-design),
    opens the browser.
  - `arrows` → serves the `.arrows` file + prints arrows.app import
    instructions (arrows.app is client-side; we pre-import via URL where
    possible, else open the file).
  - `drawio`/`canvas` → opens desktop/web app with the artifact.
- Process registry in world state: `ark view --list` (id, format, pid,
  url, started_at), `ark view --stop <id>|--all`. Orphan reaping on next
  `ark view` invocation (stale PID detection).
- Default view fixes the LikeC4 auto-index problem: adapter emits
  `view index { include target.* }` so humans see the actual graph, not
  a single root node (real-OSS finding: auto `include *` renders one
  box; `target.*` renders 600KB of real architecture).

### 3.3 `ark serve` — local Control Plane (M4, flagship)
Single binary web app (localhost), sections:
- **Progression**: fitness score & metrics over run history (sparklines:
  elements, relations, drift findings, symbols, evidence coverage).
- **Diagram**: embedded interactive LikeC4 view (web component) —
  explore the derived architecture, click an element → **evidence panel**
  (the observations/claims/evidence that produced it, with file:line).
- **Runs**: history of discover/scan/drift runs with step logs, timings,
  sha256-verified artifacts (deep-link to evidence manifest).
- **Drift & governance**: open findings → one-click `fork` + `proposal`
  draft; approval flow maps to existing promote gate.
- **Suggestions**: same `next[]` list as `ark status`, clickable.
Tech decision (ADR required): stdlib `http.server` + one static bundle
(vanilla JS + LikeC4 web component) to keep the dependency policy
(docs/v2/14) intact; OR introduce FastAPI+React if we accept the dep.
Default proposal: **stdlib + LikeC4 web component build**, no new runtime
deps; revisit if the UI grows beyond 3 pages.

### 3.4 `ark history` / `ark trend` — measurable progression (M3)
- Every `discover`/`scan`/`drift` appends a run record to the project
  registry (already exists for projects): run_id, commit, timings,
  metrics snapshot, artifact hashes.
- `ark history --json` → machine-readable run list; `ark history` → table.
- **Architecture Fitness Score** (0-100, deterministic, documented
  formula): composite of
  `drift_clean (0-30) + evidence_coverage (0-25) + model_validity (0-20,
  likec4 validate) + freshness (0-15, index vs HEAD) + review_debt
  (0-10)`. Grade A-F. Designed to be gamified: README badge, CI gate
  thresholds, trend per PR.
- `ark trend` renders sparkline (ASCII by default, PNG with likec4
  renderer present).

### 3.5 `ark ask <question>` — context for agents (M2, sellable core)
Wraps the existing ContextCompiler: parses natural goal → deterministic
intent classification → budgeted ContextPack with provenance. Output
formats: human text (default), `--json`, `--format markdown` (paste-ready
for any LLM), `--format claude|cursor` (agent-file snippets).
KPI printed with every pack: tokens (approx), source_file_reads,
budget adherence — **token economics as the hook** (landscape-validated
buying trigger).

### 3.6 `ark mcp` — MCP server (M5, distribution)
Expose the tool graph to Claude Code / Cursor / Windsurf:
`search_code`, `get_context_pack`, `get_status`, `get_drift`,
`get_history`, `explain_element`, `propose_change` (creates fork+proposal
for human approval — agents never mutate main world directly).
Differentiation vs code-graph MCPs: **semantic architecture + evidence +
governance**, not symbol graphs. LikeC4 serves hand-written models; we
serve derived reality. Dep decision (ADR): official `mcp` Python SDK
(pinned) — first third-party runtime dep if accepted.

### 3.7 `ark gate` — governance as code (M3.5, enterprise hook)
CI command: `ark gate --max-drift 0 --min-fitness 75 --fail-on stale-index`
→ deterministic exit codes, PR-ready markdown via `--report md`. Direct
answer to "fitness functions in CI" (InfoQ/CIO trend) at OSS price point.

### 3.8 `ark watch` — live drift (M5+, optional)
fs watcher (stdlib) → debounced incremental rescan → drift diff →
desktop notification + control-plane push. Stretch; not in first release.

### 3.9 Self-discovery for agents (M1, cross-cutting)
- `ark schema [cmd]` — JSON Schema for every command's output.
- `ark --help` rewritten around tasks ("inspect architecture",
  "serve context to an agent", "gate a PR") not internals.
- `ark doctor` extended: verifies likec4/semgrep/ast-grep, prints which
  `ark` capabilities are available (capability manifest).
- `ark init --agent`: writes AGENTS.md snippet + MCP client config +
  suggested PR gate — the "adopt in 30 seconds" path.

## 4. Lateral proposals (not done by anyone, cheap for us)

1. **Evidence lineage on click** (`explain_element`): control plane and
   MCP both answer "why does this element exist?" with the observation→
   claim→evidence chain and file:line — auditable architecture.
   Directly enabled by the event log; zero new storage.
2. **Architecture badge for README** (`ark badge`): fitness score +
   grade as SVG generated locally (like coverage badges). Viral loop for
   OSS adoption.
3. **PR comment reports** (`ark report pr`): markdown with fitness delta
   vs base branch ("this PR adds 2 drift findings; fitness 82→79").
   Plugs into the fork/diff machinery already proven (UAT2-013).
4. **Agent bootstrap pack** (`ark context --for-agent`): one command an
   agent runs at session start; returns the compact architecture brief
   (top elements, boundaries, forbidden relations) — the "constitution"
   of the repo, budgeted.
5. **Scan scope profiles** (quick win from the Next.js run: examples/
   dominated the graph): `ark discover --profile framework|app|monorepo`
   with sane excludes per profile; per-language semgrep rules auto-picked
   by detected stack (nextjs.yml already exists; django/axum pending).

| M | Scope | Acceptance | Effort |
|---|---|---|---|
| M1 | `ark status` + `ark view` (managed viewers) + adapter view fix + `ark schema` | status infers all states on fixtures + nextjs run; view list/stop works; likec4 index view shows real graph | 2-3 sess |

Order rationale: M1/M2 = daily-driver value + agent hook (sellable demo);
M3 = the measurable story (fitness) that M4 charts; M4 = flagship UI;
M5 = distribution. Django/Axum OSS validation (Sesiones C/D) slots in
after M1 — they double as rule-library growth and demo material.

- Fitness trend: per-PR delta, repo badge adoption.
