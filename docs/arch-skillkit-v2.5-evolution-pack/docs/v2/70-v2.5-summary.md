# V2.5 Summary — Architecture Integrity & Intelligence Kernel

## 1. Propósito

V2.5 consolida ArchSkillKit como un **Architecture Intelligence Workbench
agent-first**. El producto no se define por sus viewers sino por su capacidad
para transformar código en conocimiento arquitectónico verificable y operar
sobre ese conocimiento de forma segura.

Pipeline conceptual:

```text
source
  -> deterministic evidence
  -> normalized code/evidence graph
  -> auditable Architecture World
  -> snapshot
  -> explain / impact / context / delta
  -> proposal / simulation
  -> policy / review / gate
  -> promotion
  -> learning into deterministic sensors
```

## 2. Qué se conserva

- Python.
- ActiveGraph para el Architecture World.
- event sourcing, replay y forks.
- separación Code Index / Architecture World.
- evidence-first y repository-clean.
- `DETECTED`, `INFERRED`, `DECLARED`, `OBSERVED`.
- proyecciones recreables.
- Context Compiler.
- candidate knowledge y promoción explícita.
- RunLedger y RuntimeRegistry separados del estado semántico.
- roadmap gobernado por gates observables.

## 3. Problema que resuelve V2.5

La arquitectura conceptual ya prescribe Application API y puertos, pero el
código conserva rutas en las que:

- MCP/HTTP reutilizan handlers CLI;
- se captura `stdout/stderr` y se vuelve a parsear JSON;
- delivery construye `ArchitectureWorld`/`CodeIndex`;
- application conoce tipos concretos de CodeIndex;
- repositorios conocen la estructura de `world.graph`;
- el cumplimiento arquitectónico se comprueba sobre todo por imports/texto.

V2.5 convierte los límites deseados en propiedades ejecutables.

## 4. North Star

ArchSkillKit debe poder contestar de forma trazable:

1. ¿Qué arquitectura tenemos?
2. ¿Qué evidencia la soporta?
3. ¿Qué no sabemos?
4. ¿Qué cambió entre dos snapshots?
5. ¿Qué se rompe si modifico X?
6. ¿Qué políticas se violan?
7. ¿Qué contexto mínimo necesita un agente?
8. ¿Qué propuesta cambiaría el mundo?
9. ¿Qué pasaría si la simulamos?
10. ¿Qué claims/sensores pueden hacerse deterministas?

## 5. Definition of Done V2.5

V2.5 está cerrada cuando:

- CLI, MCP y HTTP consumen el mismo Application API;
- no existe `delivery -> delivery`;
- `application` no importa delivery, ActiveGraph, `world.py` ni CodeIndex concreto;
- `.graph` está confinado al adapter ActiveGraph;
- Composition Root centraliza wiring;
- `ArchitectureDelta` es first-class y alimenta `changes`, `impact` y gate PR;
- los gates arquitectónicos se ejecutan determinísticamente;
- la deuda de arquitectura tiene baseline versionado y tendencia monotónica a cero;
- wheel smoke funciona en entorno limpio;
- UAT obligatorio produce evidence manifest reproducible;
- ningún milestone se declara PASS sin sus gates y UAT obligatorios.
