# V2.5 Architectural Conformance and Connascence

## 1. Propósito

Medir arquitectura física, no intención.

## 2. Tipos de connascence vigilados

### Name / Value

- schema IDs;
- status strings;
- error codes;
- relation kinds.

Mitigación: enums/modelos/versioned schemas.

### Type / Structure

- `world.graph.*`;
- objetos ActiveGraph con `.id/.data/.source/.target`;
- dicts de shape implícito.

Mitigación: ports + DTOs.

### Algorithm

- normalización de IDs duplicada;
- resolución de candidates repetida;
- misma validación implementada en CLI/MCP/HTTP.

Mitigación: Application Service único.

### Execution / Timing

- ejecutar handler CLI y capturar stdout;
- orden implícito open world -> open index -> close;
- locking dentro de delivery.

Mitigación: lifecycle/composition y use cases.

## 3. Reglas ejecutables

`ARC-001` delivery no importa otro sibling delivery como API.

`ARC-002` application no importa delivery.

`ARC-003` application no importa ActiveGraph.

`ARC-004` application no importa implementación `world.py`.

`ARC-005` application no importa CodeIndex concreto.

`ARC-006` `.graph` sólo aparece en adapter ActiveGraph y código legacy
temporalmente baselineado.

`ARC-007` `Runtime`/`Graph` de ActiveGraph sólo aparecen en adapter permitido.

`ARC-008` `argparse` sólo aparece en inbound CLI.

`ARC-009` `mcp.*` sólo aparece en inbound MCP.

`ARC-010` `http.server`/routing HTTP sólo aparece en inbound HTTP.

`ARC-011` application no imprime a stdout/stderr.

`ARC-012` application no usa `redirect_stdout` como protocolo interno.

## 4. Baseline de deuda

Para migrar sin big bang:

```text
violations(main today) = baseline
```

Gate inicial:

```text
new_violations <= baseline
```

Después de cada slice:

```text
baseline' < baseline
```

Final:

```text
baseline = 0
```

Un baseline debe almacenar violaciones concretas, no sólo un número, para evitar
que una deuda desaparezca y sea sustituida por otra diferente manteniendo el
mismo count.

## 5. Determinismo

El verificador:

- usa AST Python;
- normaliza paths;
- ordena findings;
- no usa red;
- no depende de timestamps;
- produce JSON canonicalizable.

## 6. Defense in depth

El verificador propio es la fuente de verdad del proyecto.

Puede complementarse con:

- Import Linter;
- ruff;
- mypy;
- pytest architecture tests;
- ArchSkillKit dogfooding.

Ninguno sustituye los invariantes de dominio.
