# V2.5 ArchitectureDelta Specification

## 1. Motivación

`ArchitectureDelta` unifica change intelligence. Evita implementar algoritmos
incompatibles para drift, history, impact, PR gate y stale model.

## 2. Modelo

```text
ArchitectureDelta
  schema_version
  from_snapshot
  to_snapshot

  code
    files_added/removed/changed
    symbols_added/removed/changed
    edges_added/removed/changed

  evidence
    added/removed/stale/rebound

  architecture
    elements_added/removed/changed
    relations_added/removed/changed
    claims_changed

  policy
    new_violations
    resolved_violations
    unchanged_violations

  knowledge
    gaps_opened/resolved
    confidence_changed
    candidates_staled

  artifacts
    projections_staled
```

## 3. Identidad

Los sets se comparan por identidad semántica estable, no por IDs accidentales de
persistencia.

## 4. Determinismo

Mismos dos snapshots => mismo delta canonical.

Orden de arrays definido por clave semántica.

## 5. Consumidores

- `ark changes`;
- `impact`;
- `gate`;
- PR report;
- `history`;
- Context Compiler;
- projection staleness;
- architecture blame/bisect futuros.

## 6. Policy semantics

Distinguir:

- violación preexistente;
- nueva violación;
- violación resuelta.

Esto habilita políticas como `no-new-drift` sin exigir limpiar toda la deuda
histórica antes de adoptar gates.

## 7. Gate

`DELTA-DET-001`: same snapshots -> byte-equivalent canonical JSON.

`DELTA-EXPLAIN-002`: todo cambio de verdict debe ser explicable por al menos
un elemento de delta o cambio de policy revision.
