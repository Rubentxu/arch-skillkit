# ADR-0012: Arquitectura emergente gobernada por triggers

- Status: Accepted
- Date: 2026-08-31

## Context

Necesitamos mantener abiertas capacidades potentes sin convertirlas en backlog obligatorio.

## Decision

Cada gran complejidad futura tendrá trigger, spike y ADR antes de implementación.

## Consequences

### Positive

- Evita overengineering.
- Decisiones basadas en dolor real.
- Roadmap adaptable.

### Negative / Trade-offs

- Algunas capacidades atractivas se posponen.
- Requiere disciplina de producto.

## Revisit when

Nunca; este ADR define una forma de tomar decisiones, no una tecnología concreta.
