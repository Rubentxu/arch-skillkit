# V2.5 Deterministic Verification System

## 1. Objetivo

Que la arquitectura pueda demostrar su conformidad sin interpretación humana.

## 2. Pirámide de verificación

```text
             Human UAT
          Integration UAT
       Semantic/property tests
      Application contract tests
    Architecture AST/import gates
  lint/type/package/reproducibility
```

## 3. Architecture verifier

`verification/arch_conformance.py`:

- stdlib only;
- inspecciona AST;
- detecta imports prohibidos;
- detecta acceso `.graph`;
- detecta patrones de adapter crossing;
- produce findings ordenados;
- compara contra baseline exacto.

## 4. Baseline

Workflow inicial:

```bash
python verification/arch_conformance.py --root python/src/archskillkit \
  --contracts verification/architecture-contracts.json \
  --write-baseline verification/architecture-baseline.json
git diff -- verification/architecture-baseline.json
```

Este paso se ejecuta una sola vez y se revisa.

En CI:

```bash
python verification/arch_conformance.py \
  --root python/src/archskillkit \
  --contracts verification/architecture-contracts.json \
  --baseline verification/architecture-baseline.json
```

## 5. Monotonic debt rule

Si desaparece una violación, el baseline debe actualizarse eliminándola.

Si aparece otra distinta, aunque el count total sea igual, FAIL.

## 6. Hard gates

Un contract pasa de baseline-aware a hard cuando su milestone de cierre se
cumple. Entonces su baseline debe estar vacío.

## 7. Deterministic outputs

Todos los verifiers:

- normalizan path `/`;
- ordenan por `(rule_id, path, line, detail)`;
- omiten timestamps del resultado comparable;
- tienen schema versionado;
- exit 0 = pass, exit 1 = violation/config failure.

## 8. Evidence bundle

Cada milestone produce:

```text
verification-report.json
metrics.json
pytest.xml
uat-report.json
artifact-hashes.json
repo-cleanliness.json
```

El milestone manifest referencia SHA-256 de cada fichero.
