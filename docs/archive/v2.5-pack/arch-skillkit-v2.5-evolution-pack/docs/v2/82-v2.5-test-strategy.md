# V2.5 Test Strategy

## 1. Unit tests

Para value objects, policies y algoritmos puros.

## 2. Contract tests

Cada port/adaptor debe compartir contract suite.

Ejemplos:

- ArchitectureQueryPort adapter contract;
- CodeGraphQueryPort contract;
- ProjectionAdapter contract;
- ViewerAdapter contract.

## 3. Property-based tests

Prioridad alta para invariantes difíciles de cubrir con ejemplos.

### PROP-001 Replay

`replay(events).snapshot == live.snapshot`.

### PROP-002 Proposal promotion

Tras promote aprobado:

`structural_diff(main_after, candidate).is_empty()` para el scope promovido.

### PROP-003 Delta symmetry

`delta(A,A)` es vacío.

### PROP-004 Delta sensitivity

Cambio semántico mínimo altera sólo dimensiones esperadas.

### PROP-005 Projection purity

Generar proyección no altera world digest.

### PROP-006 Simulation isolation

`digest(base_before) == digest(base_after)`.

### PROP-007 Deterministic gate

Mismos inputs => mismo verdict/findings.

### PROP-008 Evidence identity

Misma evidencia canonical => mismo EvidenceId.

### PROP-009 Generation retirement

Nueva generation no deja facts de generation anterior en vista current.

### PROP-010 Delivery parity

Misma query a adapters distintos => canonical semantic result igual.

## 4. Golden tests

Usar para schemas/projections sólo cuando el formato sea contrato.

Golden debe ser estable, normalizado y reviewable.

## 5. Mutation testing selectivo

Aplicar a:

- policy evaluation;
- promotion;
- delta;
- evidence identity;
- waiver expiry.

No imponerlo globalmente hasta demostrar ROI.

## 6. OSS fixtures

Matriz mínima:

- TypeScript/Next.js;
- Rust/Axum;
- Python/Django;
- Kotlin/Spring fixture.

Fijar commit SHA.

## 7. Test determinism rules

- no red salvo suite explícita integration;
- clocks inyectados;
- temp dirs controlados;
- locale/timezone fijados;
- output sorting explícito;
- random seeds registrados.
