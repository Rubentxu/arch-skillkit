# V2.5 Migration Plan — Strangler, no Rewrite

## 1. Regla

Cada slice conserva comportamiento observable y reduce deuda arquitectónica.

## 2. Slice 0 — Measurement

- integrar verifier;
- generar baseline;
- no tocar arquitectura todavía.

## 3. Slice 1 — Governance

Extraer lógica de `delivery/cli/proposals.py` a application commands.

Antes:

```text
MCP/HTTP -> CLI handler -> stdout JSON -> parse
```

Después:

```text
CLI -> application
MCP -> application
HTTP -> application
```

## 4. Slice 2 — Composition

Introducir `ArchSkillKitApplication.for_repo`.

Primero status/governance, luego resto.

## 5. Slice 3 — ActiveGraph ACL

Crear adapter/facade pública. Mover accesos graph por aggregate, no con mega
refactor.

## 6. Slice 4 — CodeGraph port

Mover `AnalyzeImpact` y demás queries a `CodeGraphQueryPort`.

## 7. Slice 5 — CLI legacy strangler

Cuando un command legacy se modifica, migrarlo al registry/Application API.

## 8. Slice 6 — Control Plane

Reducir a routing/security/mappers. Separar UI estática.

## 9. Slice 7 — CodeIndex decomposition

Extraer ingestion/store/query en ese orden. Mantener facade compatibility.

## 10. Regresión

Cada slice exige:

- existing tests green;
- architecture baseline disminuye o permanece;
- parity tests;
- replay/snapshot digest fixtures;
- repo-clean;
- UAT del slice.

## 11. Stop conditions

Parar y reanalizar si:

- la abstracción añade más adapters/DTOs que semántica real;
- performance empeora >20% sin explicación;
- baseline no baja tras dos slices;
- parity requiere hacks de transporte;
- ActiveGraph capability importante queda artificialmente oculta.
