## 1. Objetivo

Hacer que CLI, MCP, HTTP y futuras superficies compartan semántica y no
implementación de delivery.

## 3. Command/Result policy

Un use case:

- recibe modelo tipado;
- devuelve modelo tipado;
- no imprime;
- no llama `argparse`;
- no serializa JSON como forma de comunicación interna;
- no conoce HTTP/MCP;
- produce errores de aplicación tipados.

Ejemplo:

```python
@dataclass(frozen=True)
class PromoteCandidate:
    name: str
    approved_by: str

@dataclass(frozen=True)
class PromotionResult:
    candidate_id: str
    snapshot_before: str
    snapshot_after: str
    delta: ArchitectureDelta
```

## 4. Error taxonomy

- `NotFound`
- `AmbiguousSubject`
- `PreconditionFailed`
- `PolicyDenied`
- `Conflict`
- `InvalidCandidate`
- `StaleSnapshot`
- `CapabilityUnavailable`

Cada delivery mapea estos errores:

```text
ApplicationError -> CLI exit/envelope
ApplicationError -> MCP error
ApplicationError -> HTTP status/envelope
```

Nunca al revés.

## 5. Composition Root

Responsabilidades:

- resolver `ProjectContext`;
- abrir/inyectar stores;
- construir ports;
- aplicar configuración;
- exponer `ArchSkillKitApplication`;
- garantizar cierre/lifecycle.

No contiene semántica de dominio.

## 6. Parity contract

Para una misma entrada/snapshot:

```text
canonical(application result)
==
canonical(CLI decoded payload)
==
canonical(MCP decoded payload)
==
canonical(HTTP decoded payload)
```

Se permiten diferencias de transporte, nunca de contenido semántico.
