# V2.5 Learning Architecture

## 1. Tesis

El mejor uso de LLM en el largo plazo no es repetir inferencias conocidas, sino
descubrir patrones que puedan convertirse en sensores deterministas.

## 2. Flujo

```text
repeated supported inference
  -> SensorCandidate
  -> positive/negative fixtures
  -> evaluation
  -> human/policy review
  -> SensorPackRevision
  -> deterministic detection
```

## 3. SensorCandidate

Incluye:

- pattern/rationale;
- examples;
- counterexamples;
- source prompt/skill/model;
- supporting evidence;
- languages/frameworks;
- proposed deterministic implementation;
- expected precision/recall.

## 4. Promotion gate

Un candidate no se acepta por frecuencia.

Debe superar:

- schema validation;
- positive fixtures;
- negative fixtures;
- OSS validation;
- precision threshold;
- recall threshold;
- regression gate;
- review.

## 5. KPI

- LLM calls avoided;
- token reduction;
- precision/recall;
- false-positive/negative rate;
- frameworks covered;
- deterministic runtime cost.

## 6. Invariante

`LLM -> accepted deterministic rule` directo está prohibido.
