# V2.5 UAT Plan

## 1. Filosofía

UAT valida comportamiento observable y arquitectura integrada. Unit tests y
architecture tests no la sustituyen.

Cada sesión registra:

- UAT ID;
- milestone;
- exact commit;
- fixture/OSS repo + commit;
- tool versions;
- commands/API calls;
- expected assertions;
- actual result;
- hashes;
- repo before/after digest;
- PASS/FAIL/BLOCKED;
- evidence paths.

## 2. M0 — Verification

### UAT25-001 Reproducible architecture report

Ejecutar dos veces verifier sobre mismo checkout. Canonical report SHA-256
idéntico.

### UAT25-002 Baseline detects replacement debt

Eliminar una violación baseline y añadir otra distinta. El gate debe FAIL aunque
el count sea igual.

### UAT25-003 Baseline reduction

Corregir una violación y reducir baseline. PASS.

### UAT25-004 Clean wheel

Build wheel -> venv vacío -> install wheel -> `--version` -> status sobre fixture.

## 3. M1 — Governance API

### UAT25-010 Candidate create parity

CLI/MCP/HTTP crean candidate equivalente con mismo canonical application result.

### UAT25-011 Review parity

Misma proposal y thresholds -> mismo review verdict.

### UAT25-012 Promote safety

Sin approved-by válido/preconditions => ninguna mutación main.

### UAT25-013 No delivery chaining

Architecture verifier falla si MCP/HTTP importa proposals CLI.

### UAT25-014 No stdout protocol

Architecture verifier falla si governance adapter usa redirect stdout como IPC.

## 4. M2 — Composition

### UAT25-020 Central wiring

Instrumentar constructor de outbound store; una request pasa por Composition Root
y no por adapter-specific construction.

### UAT25-021 Lifecycle

50 requests secuenciales no dejan handles/locks persistentes.

### UAT25-022 Delivery parity

Status/explain/impact en CLI/MCP/HTTP: canonical payload semantics iguales.

## 5. M3 — ActiveGraph closure

### UAT25-030 Forbidden import

Introducir import `activegraph` en application: FAIL.

### UAT25-031 Structural graph leak

Introducir `something.graph.add_object` fuera adapter permitido: FAIL.

### UAT25-032 Replay unchanged

Refactor ACL no cambia snapshot/replay semantics en fixture.

## 6. M4 — Delta

### UAT25-040 Empty delta

A vs A => empty.

### UAT25-041 Known relation delta

Añadir una dependencia controlada => exactamente una architecture relation nueva
y sus evidence refs esperadas.

### UAT25-042 No-new-drift

Base contiene 2 violations; head conserva 2 y añade 1 => gate reporta new=1.

### UAT25-043 Historical debt

Base/head mantienen violations históricas sin nuevas => política no-new-drift PASS.

### UAT25-044 Delta determinism

10 repeticiones same base/head => canonical SHA idéntico.

## 7. M5 — Code providers

### UAT25-050 Provider parity baseline

### UAT25-051 Provenance

### UAT25-052 Optional precise provider

## 8. M6 — Agent Context

### UAT25-060 Budget

ContextPack nunca excede budget.

### UAT25-061 Delta-aware focus

Cambio localizado produce menos source bytes que baseline naive sin perder facts
esperados.

### UAT25-062 Stale session

Cambio de code/world/policy revision marca sesión stale.

### UAT25-063 Unknown honesty

## 9. M7 — Learning

### UAT25-070 Candidate only

Repeated inference crea SensorCandidate pero no sensor aceptado.

### UAT25-071 Negative fixtures

Un candidate con false-positive alto no promociona.

### UAT25-072 Accepted sensor

Sensor aceptado reproduce positives, rechaza negatives y mantiene provenance.

### UAT25-073 ROI

Comparar workflow antes/después: registrar LLM calls/tokens evitados.

## 11. Pass rule

No existe “PASS manual” sin evidence manifest.

Un UAT bloqueado por dependencia externa puede marcarse `BLOCKED`, pero un
milestone no cierra si ese UAT valida una capacidad obligatoria.
